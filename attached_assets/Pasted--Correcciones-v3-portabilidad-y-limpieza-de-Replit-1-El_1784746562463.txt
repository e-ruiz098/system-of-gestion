# Correcciones v3 — portabilidad y limpieza de Replit

## 1. El script de arranque del backend no debe depender de rutas ni de sintaxis de Replit
El script que levanta `api-server` tiene grabada una ruta absoluta que solo existe
dentro del entorno de Replit, y además usa una sintaxis de consola que solo
funciona en Linux/Mac. Hay que reescribirlo para que:
- No dependa de ninguna ruta fija de ningún entorno en particular. La ubicación
  del archivo de base de datos debe calcularse de forma relativa al proyecto
  (o tomarse de una variable de entorno opcional, con un valor por defecto que
  funcione sin configurar nada), nunca escrita a mano apuntando a una carpeta
  que solo existe en un servidor de Replit.
- Funcione igual en Windows, Mac y Linux. Nada de instrucciones de consola que
  solo entienda una terminal tipo Bash — tiene que arrancar igual desde
  PowerShell, cmd o una terminal de Mac/Linux, sin que el usuario tenga que
  cambiar de terminal ni instalar nada adicional para lograrlo.

## 2. Eliminar toda dependencia y complemento de Replit del proyecto
Quitar por completo, de todos los `package.json` del proyecto (raíz, backend y
frontend), cualquier paquete cuyo nombre empiece con "@replit/" — incluyendo el
que permite conectarse a servicios propios de Replit, y los tres complementos
de Vite que agregan el cartel de "Made with Replit", el modal de errores de
Replit, y el mapa de navegación de Replit. Junto con quitar esos paquetes,
también hay que quitar cualquier línea en la configuración de Vite que los
importe o los active — no alcanza con desinstalar el paquete si el código
todavía intenta usarlo condicionalmente.

## 3. Eliminar archivos y carpetas de configuración propios de Replit
Borrar del proyecto cualquier archivo o carpeta que exista únicamente para que
Replit sepa cómo ejecutar o mostrar el proyecto dentro de su propio entorno:
el archivo de configuración raíz de Replit, cualquier archivo de configuración
de "artifact" de Replit dentro de las distintas carpetas del proyecto, y
cualquier documentación o metadato que Replit haya generado sobre sí mismo.
Nada de esto es necesario para que la aplicación funcione fuera de Replit.

## 4. Eliminar la carpeta de "mockup-sandbox"
Esa carpeta es una herramienta interna que la IA usó mientras diseñaba los
componentes visuales, no es parte de la aplicación final que el dueño del
negocio va a usar. Se puede eliminar por completo del proyecto sin afectar el
funcionamiento del sistema real (backend + frontend de POS).

## 5. Revisar si quedan carpetas de estado interno del agente de Replit
Si existen carpetas ocultas que Replit usa para guardar su propio estado interno
o el de sus "habilidades" (todo lo que no sea el código fuente del backend, el
frontend, y las librerías internas del workspace), también se pueden eliminar.
El proyecto final debería poder copiarse a cualquier computadora y funcionar
solo con el código fuente real de la aplicación, sin ninguna carpeta que
dependa de haber sido creado dentro de Replit.
